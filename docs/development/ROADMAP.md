# 数据抓取与清洗平台路线图

状态：当前执行阶段 1B；1A 工程验收已通过，产品负责人验收待完成

## 1. 简单说明

项目只有两个阶段：先把真实原始数据抓回来，再讨论怎么清洗。1A 已完成自动化与真实 PC 工程验收，仍由产品负责人最终审查草稿质量；用户已经明确授权开发 1B 的最小抓取规划纵切片，但这不授权提前建设 Provider 或访问真实来源。

## 2. 阶段 1：数据抓取

### 1A 对话生成抓取任务

产物：标准商品的版本化抓取任务草稿和用户确认后的正式抓取任务。

通过门：

- 首句门类直接生效；
- 系统先判断标准商品边界，主动调查标准、品牌、型号、参数和来源，不让用户枚举可查事实；
- 每个负责人问题都是真实取舍，在普通消息中给出专业推荐、依据和主要代价；不得为了凑选项制造问题，Composer 同时接受建议之外的回答；
- 家电必须包含京东平台来源并解释原因，不询问“是否纳入京东”；淘宝作为后续多平台来源；
- 草稿明确标准商品边界、抓什么、平台/官方来源、候选入口和未决项；
- 确认不触发真实抓取。

### 1B 真实来源 Crawl Plan

用户已于 2026-08-19 授权按 `CRAWL-PLANNING-DESIGN.md` 开发。针对一个已确认 Capture Task revision，先用可见 Planning Run 形成版本化计划草稿；计划必须回答：

- 来源角色、真实入口和访问状态；
- 捕获 HTML、JSON、PDF、CSV/XLSX、图片或其他哪种源站单元；
- 抓取对象、覆盖分母、数量、分页/遍历终止；
- 唯一键、遍历方式和停止条件；
- Provider、许可、登录、验证码、风控、频控或持久化尚未验证时的执行阻塞项。

当前 1B 只实现计划生成、审查、修订和确认，不实现 Provider 或真实批量来源访问。计划确认不创建 Source Run。

用户确认计划前不得发真实批量请求。

### 1C 单一真实来源闭环

从一个真实来源抓取一批未清洗数据，写入正式本地数据区；重启 API/Web 后仍可查看；JSONL/CSV 或原文件可以导出；数据库计数、导出记录和来源标识一致。

### 1D 京东闭环

在许可、登录状态和频控通过后，依次验收：分类/筛选、品牌、自营/旗舰店、商品详情/参数/媒体、评价样本和评分指标。不得绕过验证码、风控或用途限制。

### 1E 淘宝、多来源和更新

只有单来源与京东纵切片通过后，才为淘宝制定独立计划并逐步增加品牌官网、监管/标准和技术来源，验证多平台覆盖、增量抓取与跨来源任务恢复。

## 3. 阶段 2：数据清洗

阶段 1 全部通过后另行访谈和设计。输入只能是阶段 1 的不可变原始数据；清洗结果必须与原始数据物理或逻辑分离。当前不建设 Evidence、知识候选、Review、知识包或 Runtime。

## 4. 停止规则

- 1A 的产品负责人验收未完成，且用户未明确授权时，不进入新的后续实现；本次 1B 规划纵切片已有 2026-08-19 明确授权；
- 非标准商品不进入当前采访和抓取流程；
- Crawl Plan 未确认，不访问真实来源；
- 京东频控、熔断、登录/验证码停止条件未验证，不运行京东抓取；
- 不新建 POC package、隔离数据库或平行应用；
- 测试绿灯不能代替 Workbench 真实路径验收。
