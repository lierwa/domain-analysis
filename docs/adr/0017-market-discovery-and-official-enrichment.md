# ADR 0017：以市场目录发现和品牌官网补齐取代京东详情抓取

- 状态：Superseded by ADR 0018
- 日期：2026-08-24
- 影响阶段：ROADMAP 1B、1D、1E

## 背景

项目目标是为标准商品专业导购取得可追溯的品牌、型号、官方参数和说明书原件。真实验证已经证明：京东匿名目录能返回有价值的商品卡和图片 URL；匿名详情只返回客户端骨架；Playwright 专用登录后首条详情仍是骨架并触发账号异常。继续把“京东必须覆盖”实现成“京东详情、参数和评论必须抓到”，会把系统推向已被停止门禁止的账号和反检测对抗，也无法证明品类完整性。

## 决定

1. 京东在阶段 1 的职责收窄为匿名公开市场目录发现：类目、筛选、品牌、分页、商品卡和卡片/变体图片 URL。
2. 京东商品详情、店铺、评论和图片字节不再属于当前 Capture Task 默认范围，也不进入新的可执行 JD Provider。
3. 品牌身份、型号、官方参数、规格页和说明书由品牌官网及其公开附件补齐。
4. 用户仍拥有一个逻辑 Capture Task；系统内部允许多个经过确认的 Crawl Plan version 和 Batch，依次完成市场发现、官网补齐和缺口修复。
5. Source Dataset 继续拥有不可变原始事实；品牌、分页、型号和官网资料覆盖由可从 Snapshot 重建的 Coverage Projection 表达，不建立阶段 2 知识事实源。
6. 新发现的品牌和官网不能由正在执行的 Source Run 自动扩展范围，必须回到新的 Planning Run 和人工确认门。
7. 历史 `jd.catalog-product@2.0.0` 计划和数据保留只读，但该 Provider version 不再注册执行；新语义使用 `jd.catalog-market@1.0.0`，禁止静默迁移历史计划。
8. 官网目录能力必须先按 `RESEARCH.md` 完成三个代表性品牌 POC；未通过前保持候选，不冻结通用 production contract。

## 理由

- 目录页已经以较少请求取得市场可见商品卡，符合“京东上获取能获取的”边界；
- 品牌官网是型号、规格和说明书的第一方来源，来源职责更清楚；
- 分母和缺口对账可以失败关闭，避免用“抓到一些页面”冒充完整；
- 保留现有任务、计划、执行、队列和原始数据 seam，只替换错误来源职责，改动比继续叠登录/详情 fallback 更小；
- 新 key/version 让历史错误计划安全失效，避免公共 contract 的语义漂移。

## 后果

正面：

- 删除账号登录和详情反检测路径，降低账号与合规风险；
- 京东请求面显著缩小；
- 用户能看到品牌/型号/资料缺口，而不是在批次列表中猜完成度；
- 后续品牌官网差异由薄 adapter 隔离，不污染跨品类 Source Dataset。

代价：

- 京东公开目录中的原始标题不一定包含精确型号，必须在官网阶段显式匹配；
- 官网不公开、sitemap 不完整或站点受限时，任务只能是 `partial`；
- 同一个用户任务会产生多个计划版本和批次，但 UI 必须把它们折叠为一个整体覆盖视图；
- 需要一次破坏性 contract 升级，历史 JD v2 计划不能继续执行。

## 被否决方案

- 继续 Playwright 登录并调延迟：真实账号异常已经否决；
- 代理池、指纹伪装、账号轮换或验证码绕过：不符合现有停止门，也不解决覆盖分母；
- 只用 `public.web-resource` 抓几个手工 URL：不能证明品牌官网目录和型号覆盖；
- 恢复旧 `MarketUniverse` / Knowledge Factory：会越过阶段 1，形成第二事实源；
- 建立万能 crawler/plugin 平台：当前没有足够真实来源调用方，复杂度高于收益。

## 验证门

- 删除登录、详情、评论和 canary 路径；
- 新 JD Provider 的本地网络 fixture 对详情域名、评论接口和图片 CDN 均为零请求；
- Coverage Projection 可从不可变 Snapshot 重建；
- 三个结构不同的电视品牌官网完成 sitemap/目录/说明书 POC，才允许冻结官网目录 Provider；
- 真实请求仍需逐来源单独授权，首次访问限制立即停止。

## 被替代说明

2026-08-24 的真实 Workbench 批次证明京东匿名目录仍只有一个静态种子页、0 品牌和未知分母，不能承担市场品牌发现。负责人随后明确决定当前正式规划不再包含京东，改由 Planning Agent 深度搜索品类品牌与官方来源。新的当前决定见 ADR 0018；本 ADR 只保留登录/详情路线为何被否决的历史证据。
