# 教育研究平台页面使用受控成熟浏览器采集

用户明确决定京东不走开放 API 或商务合作路线，首轮以科普教育研究为目的采集京东官方自营和经核实官方旗舰店的公开商品资料；淘宝登记为京东闭环后的下一平台来源。工程不得自研反检测、指纹或浏览器基础设施；复用现有 Crawlee 队列、状态分类和最小不可变证据边界，具体浏览器连接器必须通过 R-012 当前真实页面原型后才能进入生产依赖。

## 边界

- 只采已确认范围内的公开商品资料，不采普通第三方商家、订单、购物车、账户资料或与商品知识无关的用户数据。
- 若来源确实要求账号登录或验证码，只允许用户在本地专用 Profile 完成；不读取密码，不自动解验证码，不切换账号规避限制。登录不得在没有页面证据时被写成公开规格采集的业务前置。
- 并发固定为 1，默认不重试；风险页、登录页和空骨架必须被明确分类，不能伪装为成功。
- Cookie、认证 Header 和 Profile 不进入日志、Git、Codex 输入或知识包。2026-08-15 起按 ADR-0011，登录态整页只可在本机临时读取；只有围绕 EvidenceRequest 选择、通过隐私和最小化门的 EvidenceItem 能进入候选加工。ADR-0005 的受限快照/投影路径已被取代。
- 任一浏览器连接器不能只凭 README、历史样本或本地空白页进入生产依赖。阶段 1A 先以隔离 POC 验证至少三个当前正常 SKU、一个异常状态、内容完整性、中断恢复和最小权限，再决定 Provider 组合方式。
- 页面适配只实现来源特有的薄配置和提取规则；队列、浏览器控制、滚动、指纹和证据存储继续复用成熟开源组件。

## 已验证事实

同一台本机 Chrome 的本地空白页对照中，原版 Playwright 报告 `navigator.webdriver=true`，Patchright 报告 `false`。同一京东登录 Profile 下，S01 由原版 Playwright 进入风险响应页，改用 Patchright 后返回真实商品页、HTTP 200 且型号存在；这只证明来源访问和状态识别资产可复用。历史 POC 保存过 HTML、纯文本、截图和资源路径，但该持久化范围已由 ADR-0011 撤销。隔离 Crawlee 3.18.1 的公开样本中断恢复仍作为队列/恢复组件证据：首轮只完成 1 条，重启后只补齐剩余 2 条并正常退出。

## 2026-08-16 当前页面复核

相同时间、相同京东 SKU 的最小差分推翻了“复用已登录 Profile 即可恢复”的假设：旧、新、无 Profile 的 Patchright 均进入风险页，Playwright 得到空骨架，Puppeteer 进入频控页，普通 Chrome＋CDP 的临时专用 Profile 进入登录页；Codex 内置 Browser 在仍显示未登录提示时却能读取 26 项公开规格。故登录不是该公开规格页的业务前置，历史 Patchright 成功样本也不能继续证明当前生产可达。

Patchright 不再是当前优先生产浏览器候选；Crawlee 队列、详情 parser、typed 状态分类、失败隔离和历史 POC 证据继续保留。Codex Browser 只在桌面会话表面可用，Chrome DevTools MCP 连接可信现有 Profile 又需要用户现场授权并暴露整个所选 Profile；两者当前都没有通过 Workbench 可调用、无人值守、最小权限和恢复门。R-012 未选出替代连接器前，京东来源必须保持 scoped blocking unknown，不复制 Cookie/Profile、不复刻签名、不从标题猜型号，也不得把一次会话内手工采集冒充生产 Provider。
