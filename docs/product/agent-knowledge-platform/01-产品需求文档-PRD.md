# Agent 知识生产平台 PRD

版本：V1.0
MVP：京东－冰箱
文档性质：产品需求基线

## 1. 文档边界

本文档只回答：为谁解决什么问题、产品如何工作、MVP 做什么、怎样验收。

本文档不规定代码接口、数据库表、文件目录、爬虫选择器或最终技术栈。相关内容由工程师在《总体技术方案》约束下另行设计。

## 2. 产品要解决的问题

Agent 要可靠地完成购物引导、昆虫研究等专业任务，不能只依靠模型记忆，也不能简单把网页切块后做向量检索。

真正的问题是：

- 来源分散且持续变化；
- 原始页面结构不同，内容可能缺失、冲突或藏在图片中；
- 同一对象存在别名、不同规格和多种表达；
- Agent 需要结构化筛选、比较和证据，而不仅是相似文本；
- 知识生产过程较重，但 Agent 查询应当轻量、稳定、可离线使用。

因此产品必须同时解决“搜集原始资料”和“加工 Agent 知识”两件事，并把两者分开管理。

## 3. 产品定义

本产品是一个面向 Agent 的通用知识生产平台：

```text
一个或多个数据搜集板块
        ↓
可追溯的原始资料
        ↓
通用知识库加工厂
        ↓
版本化知识包
        ↓
本地或远程 Runtime
        ↓
目标 Agent
```

首个落地场景是“购物引导 Agent－冰箱－京东”，但知识加工厂、知识包和 Runtime 不能写死商品概念。

## 4. 用户与使用场景

### 4.1 知识项目负责人

定义 Agent 目标、确认资料范围、启动流水线、处理异常并决定是否发布知识包。MVP 中由用户本人承担。

### 4.2 数据维护者

维护来源登录状态、采集范围、失败任务和来源变化。MVP 中可与项目负责人是同一人。

### 4.3 Agent 开发者

下载或连接知识包，通过 Runtime 让 Agent 查询、筛选、比较并取得来源证据。

## 5. 核心产品对象

| 对象 | 产品含义 |
| --- | --- |
| 知识项目 | 围绕某个 Agent 目标长期维护的工作空间 |
| 数据搜集板块 | 针对一个来源和一个资料范围的可独立运行单元，例如“京东－冰箱” |
| Provider | 某个来源的接入能力，例如京东接入能力；可被多个搜集板块复用 |
| 领域知识模板 | 描述目标 Agent 需要哪些概念、关系、质量规则和评测问题 |
| 任务流水线 | 管理一次从范围确认到知识包发布的完整运行 |
| 知识库加工厂 | 把不同板块的原始资料加工为可验证知识的通用能力 |
| 知识包 | 可下载、版本化、可被 Runtime 加载的知识交付物 |
| Runtime | 向 Agent 提供知识查询和包版本管理的轻量运行环境 |

Provider 不等于数据搜集板块。“京东 Provider”是来源能力；“京东－冰箱”是本次 MVP 的业务搜集板块。

## 6. MVP 场景

### 6.1 目标

用户创建一个冰箱购物引导知识项目，系统协助制定品牌与参数矩阵，从京东持续搜集原始商品资料，经加工、审核和评测后生成一个可被 Agent 使用的冰箱知识包。

### 6.2 研究范围规划

系统首先根据“冰箱购物引导 Agent”目标生成候选研究范围，包括：

- 冰箱品牌清单；
- 产品类型与使用场景；
- 用户选购时应关注的参数与能力；
- 型号、规格、价格与在售状态等资料范围；
- Agent 最终必须能够回答的典型问题。

用户可以增删、合并和调整优先级。未经确认的范围不能直接进入正式采集。

采集计划必须由“品牌 × 产品类型 × 型号/规格 × 关注参数”的矩阵驱动，而不是随机抓取一批搜索结果。产品目标是在已确认范围内尽可能覆盖全部候选型号，并对无法覆盖的部分给出明确缺口，不能宣称无法证明的“全量”。

### 6.3 首批资料对象

MVP 重点覆盖：

- 品牌、系列、型号、SKU/规格；
- 标题、卖点、规格参数和详情说明；
- 价格、促销、库存或上下架状态及其采集时间；
- 主图、详情图及图片中需要识别的关键信息；
- 商品页 URL、采集时间和字段证据位置。

价格和状态属于时点信息，不能被包装成永久事实。

## 7. 用户主流程

| 阶段 | 用户看到和完成的事情 | 阶段结果 |
| --- | --- | --- |
| 1. 创建项目 | 填写目标 Agent、主题和期望能力 | 项目目标 |
| 2. 规划范围 | 系统生成品牌、参数和问题矩阵，用户确认 | 已确认研究范围 |
| 3. 配置搜集板块 | 选择京东来源、范围、更新方式并检查登录状态 | 京东－冰箱板块 |
| 4. 执行采集 | 查看发现量、成功量、失败原因；必要时人工登录或处理验证 | 原始资料集合 |
| 5. 知识加工 | 系统完成抽取、标准化、对象合并和冲突发现 | 候选知识 |
| 6. 人工审核 | 用户处理低置信度、冲突、异常和无法判断的内容 | 审核后的知识 |
| 7. 构建与评测 | 系统生成知识包，并用 Agent 问题集评测 | 候选知识包与报告 |
| 8. 发布与使用 | 用户激活版本；Agent 本地加载或连接 Runtime | 已发布知识版本 |

上述过程必须作为一次可暂停、可恢复、可重试的任务流水线运行，而不是一组互不关联的脚本。

## 8. 产品需求

### 8.1 项目与流水线

- 能创建、复制、暂停和归档知识项目。
- 每次流水线必须冻结当次范围、来源、处理规则、模型和知识包版本信息。
- 每个阶段显示进度、结果、失败原因和待人工处理事项。
- 中断后能够继续，不要求从头重跑。
- 允许基于旧原始资料重新加工，不必重新访问京东。
- 增量更新必须生成新版本，不覆盖历史结果。

### 8.2 数据搜集板块

- MVP 只提供“京东－冰箱”板块。
- 用户能够维护采集范围、优先级、更新频率和启停状态。
- 支持用户本人在本地完成京东登录和验证。
- 遇到登录过期、验证码、限流或页面异常时暂停并明确提示，禁止静默跳过。
- 原始页面、必要的页面数据和采集上下文应被保存，供后续重放和举证。
- 系统显示候选资料数量、已采集数量、失败数量、重复数量和覆盖情况。
- 覆盖率必须相对于用户确认的品牌与产品矩阵计算，不能只统计已加入队列的 URL。
- 采集可以慢，MVP 优先保证可恢复、可核查，不追求高并发。

### 8.3 知识库加工厂

- 不假设抓回来的数据已经干净或结构统一。
- 同时使用确定性解析、领域规则、必要的模型判断和人工审核。
- 能发现候选字段和表达差异，并由用户确认关键知识范围。
- 保留原始值、标准值、推断状态和来源证据。
- 处理单位、枚举、别名、重复对象、多规格和冲突来源。
- 模型结果不能直接成为已发布事实；必须通过校验并绑定证据。
- 对无法确定的内容进入审核队列，不得编造补齐。
- 加工逻辑应能替换模型服务，不绑定单一模型厂商。

### 8.4 知识包与 Runtime

- 知识包必须独立于采集和加工环境，可下载、复制和离线保存。
- 每个知识包有明确身份、版本、适用领域、来源范围和质量状态。
- Agent 至少能够进行精确查询、条件筛选、全文搜索、对象关联查询和证据查看。
- 查询默认不要求调用模型、生成 embedding 或连接向量数据库。
- Runtime 支持加载、激活、切换和回滚知识包版本。
- Runtime 的通用能力不出现商品专用命名；购物比较能力由冰箱知识包提供。
- Agent 可选择直接在本地加载，也可连接一个已加载该包的轻量服务。

### 8.5 本地与线上边界

- 采集、解析、模型处理、清洗、人工审核、评测和建包只在本地电脑执行。
- 登录状态、Cookie、浏览器资料和未脱敏原始资料只保存在本地。
- 后续线上部分只管理项目维护信息、板块健康状态、知识包、Runtime、权限和审计。
- 线上服务器不得提供执行采集或知识加工的入口。
- 2 核 4G 服务器只作为未来轻量管理与 Runtime 的目标约束，不承担浏览器和模型处理。

## 9. MVP 范围

### 9.1 必须交付

- 本地项目与流水线管理。
- AI 辅助生成并确认冰箱品牌、参数和问题矩阵。
- 一个“京东－冰箱”数据搜集板块及京东 Provider。
- 原始资料保存、任务恢复和人工登录/验证接管。
- 规则、模型与人工协同的知识加工流程。
- 冲突和低置信度审核。
- 通用知识包生成与本地版本管理。
- 轻量 Runtime 和一个 Agent 接入演示。
- 评测报告和来源证据查看。

### 9.2 不在 MVP 内

- 淘宝、天猫、Amazon 或品牌官网采集。
- 多来源商品对齐。
- 服务器端采集、清洗或建包。
- 完整线上管理平台。
- 向量数据库和必须依赖 embedding 的查询链路。
- 面向消费者的最终聊天产品。
- 第二个完整知识领域的生产建设。

## 10. MVP 验收

### 10.1 验收数据集

使用用户确认的冰箱范围建立验收集：不少于 5 个品牌、50 个有效商品型号，并包含多规格、促销、缺货/下架、图片参数和页面异常样本。

该验收集用于验证系统能力，不代表“已经覆盖京东全部冰箱”。系统必须如实显示范围和未覆盖部分。

### 10.2 通过条件

- 用户能够从创建项目开始，完整跑通一次流水线并得到可加载知识包。
- 计划内且当时可访问页面的原始资料成功保存率不低于 90%；失败项均有明确状态。
- 已发布知识结论的来源可追溯率为 100%。
- 人工抽检的核心字段准确率不低于 95%，抽检规则随验收集一并冻结。
- 流水线中断后可以从最近完成阶段继续。
- 同一批原始资料可在不重新采集的情况下重新加工并生成新版本。
- 预设 Agent 任务集通过率不低于 90%，且回答能够返回证据。
- Runtime 查询不依赖模型、网络或 embedding 服务。
- 知识包可以在另一台机器加载，并完成版本切换和回滚。

## 11. 后续路线

MVP 验收后，优先增加“淘宝－冰箱”板块，验证多个数据搜集板块汇入同一知识项目；之后再建设线上知识包管理与 Runtime 部署。新增昆虫等领域时，只增加领域知识能力，不得把商品结构扩散到平台通用层。
