# 标准商品数据抓取与清洗平台文档导航

版本：V2.0
更新日期：2026-08-19

## 1. 当前产品边界

项目只包含两个阶段：先抓取并保存真实原始数据，再基于不可变原始数据设计清洗。当前只实施阶段 1。

当前服务对象是能够通过品牌、型号、规格、分类或标准稳定识别的标准商品，例如冰箱、电视机和其他家电/消费电子。手工制品、孤品、定制品等非标准商品不属于当前范围。

目录名 `agent-knowledge-platform` 是为避免打断既有仓库链接而暂时保留的历史路径，不代表当前产品仍是知识包平台。

## 3. 当前统一结论

- 用户从 Workbench Chat Timeline 输入“抓冰箱”“抓电视机”等自然语言需求。
- 专业抓取任务顾问先调查标品边界、标准/监管资料、品牌/型号结构和候选来源，再只询问必须由负责人决定的真实取舍。
- 用户不是专业抓取工程师。Agent 必须解释判断过程，并给出有依据的推荐答案；不能为了凑互斥选项制造没有业务意义的问题。
- 对适合电商平台覆盖的标准商品，平台范围属于系统应主动规划的数据资源。冰箱等家电必须包含京东；淘宝作为后续多平台来源，不把“是否纳入京东”设计成负责人问题。
- 对话产出版本化抓取任务草稿；用户整体确认后成为正式 Capture Task，但不会自动开始抓取。
- 后续按已确认任务为每个真实来源制定 Crawl Plan；计划确认前不运行真实批量访问。
- 原始 HTML、JSON、CSV、PDF、XLSX、图片、视频等按来源真实格式保存为不可变 Source Dataset；阶段 1 不提前清洗或套统一参数模板。
- 访问必须遵守许可、登录、频控、验证码和风控停止条件，不自动绕过。
- 阶段 2 只消费阶段 1 的不可变原始数据，当前不建设 Evidence、Knowledge Factory、知识包或 Runtime。

## 4. 阅读顺序

发生冲突时按以下顺序处理：

1. `01-产品需求文档-PRD.md`；
2. `02-总体技术方案.md`；
3. `05-MVP实施计划.md`；
4. `docs/development/README.md` 规定的工程权威顺序。

当前开发入口是 Roadmap 1B 的最小规划纵切片：在已确认 Capture Task 上可见地生成、修订和确认 Crawl Plan。1A 的专业判断与问答质量仍待真实 PC 人工验收；用户已明确授权本次 1B 实现，但没有授权 Provider 或真实来源访问。
