# ZOL 门类品牌与型号采集设计

状态：已确认，等待开发验证
更新日期：2026-08-28

## 1. 目标

建立一条可执行、可对账、可恢复的 ZOL 单来源链路：

```text
门类品牌发现
  -> 品牌优先级
  -> 一个 P1 品牌的当前型号目录
  -> 每个型号的参数与配置
  -> 两个 P1 品牌的受控并行
```

第一轮以 ZOL 当前型号目录为完成分母。停产型号、图片下载、评论、报价跳转和其他来源不在本轮范围。

## 3. 抓取步骤

### Z0：门类定位

输入是 Capture Task 中确认的门类名称。计划必须把它映射到 ZOL 唯一门类入口；名称冲突或门类边界不明确时停止。

产物：门类 key、门类 URL、ZOL 分类 ID、观察时间。

### Z1：全部品牌发现

访问一次门类首页，保存原始 HTML，并提取页面公开的全部品牌名称、品牌链接和来源侧产品数量。

原始品牌文本不改写；调度使用由品牌链接或 ZOL 品牌标识形成的稳定 brand key。重复显示项不能产生重复品牌任务。

产物：原始品牌快照、规范化调度清单、重复或歧义记录。

### Z2：品牌优先级

读取同门类的 ZOL 品牌排行榜，按关注占比降序排列：

1. 从第一名开始累计关注占比；
2. 达到约 80% 时形成 P1 候选；
3. 对每个 P1 候选做一次公开搜索，确认品牌仍有活跃的该门类产品线；
4. 其余已确认品牌进入 P2；无产品、身份歧义或极低活跃度品牌进入 P3。

P1 表示抓取优先级，不表示产品质量结论。品牌评分、关注占比和产品数量必须保留来源 URL 与观察时间。

### Z3：一个 P1 品牌的型号目录

先选 P1 排名第一的品牌。按品牌目录分页顺序抓取：

1. 保存每一页原始 HTML；
2. 提取型号名称、产品 URL、ZOL 产品 ID、列表页参数摘要；
3. 用 ZOL 产品 ID 作为本来源稳定去重键；
4. 直到品牌页声明的当前总数与分页遍历结果对账，或触发停止条件。

品牌页单独提供的停产入口不进入第一轮分母。

### Z4：型号参数与配置

每个型号至少捕获完整参数页原始 HTML。参数页需要观察到以下区块中的至少一个，并保存页面实际出现的全部字段：

- 基本参数；
- 技术参数；
- 功能特点；
- 其他尺寸与重量；
- 包装附件。

列表标题和参数页对应不上、产品 ID 缺失或参数页不属于当前门类/品牌时，该型号记为失败或歧义，不猜测补值。

### Z5：两个 P1 品牌受控并行

单品牌链路通过后，选择 P1 的前两个品牌：

- 两个品牌各自拥有分页和型号工作项；
- 调度器在品牌之间轮转取任务；
- 所有 ZOL 页面请求共享一个 origin gate；
- 初始仍为每分钟最多 2 次、最小间隔 30 秒；
- 解析、写盘和数据库提交可以并行；
- 运行结束后分别对账两个品牌的完成与缺口。

只有独立放量验证通过，新的 Crawl Plan 才能使用每分钟 4 次、最大网络并发 2。运行时不得自行提高速率。

## 4. 请求与停止规则

每个真实请求都必须：

1. 绑定 run、target、brand、work item 和 requested URL；
2. 在出网前通过共享 Source Access Gate；
3. 记录开始时间、最终 URL、状态、字节数和结束结果；
4. 保存不可变原始响应和父页面发现关系。

立即停止条件：

- robots 不允许；
- HTTP 401、403、429；
- 登录、验证码或风险验证正文；
- 跳转到计划外 origin；
- 页面结构无法识别门类、品牌、产品 ID 或参数区块；
- 请求预算、最长运行时间或人工停止触发。

## 5. 快速验证

### V0：7 页面单品牌纵向验证

- 1 个门类页；
- 1 个品牌排行榜；
- 2 个同品牌型号列表分页；
- 3 个型号参数页。

通过条件：品牌入口可提取、P1 可重算、分页关系稳定、型号 ID 可去重、参数区块可识别、原始页面和请求事实可查看。

### V1：6 请求双品牌调度验证

- 两个 P1 品牌各 1 个列表页；
- 每个品牌各 2 个型号参数页；
- 两个品牌任务交错执行，共享同一 origin gate。

通过条件：请求间隔满足计划、没有突发并发、两个品牌均有进展、失败不会让另一任务绕过 gate、重启后队列和 Source Dataset 状态可恢复。

### V2：独立放量验证

V1 通过后才允许制定 V2。V2 最多 10 个页面，请求上限为每分钟 4 次、最大网络并发 2；任何访问限制立即结束，并保留当前 2 次/分钟基线。

## 6. 第一轮开发顺序

1. 核对现有 Provider、RequestQueue、Source Access Gate 和 Source Dataset 能否直接表达 Z0–Z4。
2. 只实现缺失的 ZOL source adapter 与最小调度接线。
3. 运行 V0，审查实际品牌、型号、参数原文和数据库事实。
4. V0 通过后运行 V1。
5. V1 通过后再决定是否制定 V2 和 P1 批次计划。

## 7. 完成标准

- 一个门类的品牌清单有原始快照和稳定调度键；
- P1 清单可根据同一来源数据确定性重算；
- 一个 P1 品牌的当前型号分母、分页和已完成数量可对账；
- 每个成功型号都有不可变参数页原文；
- 多品牌任务共享同一控频事实源；
- 运行停止、失败和剩余队列可恢复；
- Workbench 能查看本轮原始记录和覆盖缺口。
