# 文字知识包样本验证

实验日期：2026-09-03。输入依据见 [固定样本清单](KNOWLEDGE-PACK-SAMPLE-INPUT.md)，候选与停止门见 [RESEARCH.md](RESEARCH.md) R-014，当前完成度见 [PROGRESS.md](PROGRESS.md)。

本报告保留首次文字消费实验的输入和判定口径。后续已明确“有歧义的字段不进入回答材料”，当前样包仍包含全部 OCR 候选，尚未实现该筛选；加工目标与合格条件见 [最小加工规范](KNOWLEDGE-PACK-PROCESSING.md)。

## 简单说明

将固定资料整理成一个可以在 Codex 中使用的 Skill 文件夹：目录负责找到型号，正文保留参数、图片文字及来源。加工使用本地规则，模型只参与最后的问答测试。

本样本交付文字包及原始文字对照，检查“资料能否被正确读取、回答能否回查、读取成本是否改善”。生产产线、跨品类规则和批量去水印继续由各自验证门决定。

## 实验输入与产物

| 项目 | 证据 |
| --- | --- |
| 输入 | 固定 4 个型号、11 份 HTML、12 张 JPEG；原始 Source Dataset 保持不变 |
| 附件完整性 | 11 份 HTML 的 UTF-8 payload 哈希/bytes 与持久记录一致；12 张原图 SHA-256 一致 |
| 文字保真 | 77 个参数字段及 92 行 OCR 原文/位置逐项核对通过；15 项关键 HTML 检查通过 |
| 原始文字组 | 24 个文件，104,376 bytes；HTML 全文文字、OCR 原文与来源目录 |
| Skill 组 | 6 个文件，37,706 bytes；SKILL.md、INDEX.md、4 份型号 references |
| 组装 | 约 2.35 秒；LLM 调用 0 次；复用既有 OCR 结果 |
| Skill 格式 | skill-creator 的 quick_validate.py 通过 |
| 本机路径 | data/knowledge-pack-ocr-20260903/sample-pack/ |

原始文字组去除脚本、样式和“纠错”操作文案，保持正文顺序。加工组保留完整参数表、来源图片缺失标记和全部 OCR 候选；图集其余网页文字只保留在原始文字组。两个目录的 OCR 文字、位置和复核状态相同。此对照衡量本小样的筛选与组织收益，不能外推到被筛除的其他网页信息。

每条参数含原字段、原值、Snapshot ID 与 CSS 字段定位；OCR 含 Asset/Snapshot、行号、位置、原分类、序号、哈希及父页面。父关系继承来源 URL，所列 HTML 版本是本次固定选择的版本，不能据此断言采集时父快照已严格绑定。

## 问题集与验收口径

在模型运行前冻结 8 个问题和答案锚点，保存于消费目录之外。前 6 题检查 HTML，第 7、8 题检查 OCR 文字消费；OCR 与原图的关键数字确认另记，不把模型复述正确当成识别准确率。

下表是原实验规格。Q7/Q8 未执行；后续采用新入包规则时，歧义字段应被隔离，回答说明资料不足。新版本另存题目与结果，原规格不改作新规则的通过证据。

| 题号 | 检查内容 | 通过要求 |
| --- | --- | --- |
| Q1 | 4 型号容量 | 型号、数值、单位分别对应，并引用 4 个来源 |
| Q2 | 格兰仕 700W | 保留“产品功率”；证据不足时不改称微波输出功率 |
| Q3 | 格兰仕噪音 60 | 说明原文无单位，不补写 dB |
| Q4 | 松下 4 类功率 | 输出 1000W、烧烤 1350W、蒸汽输出 1000W、烘烤输出 1450W；保留字段差异 |
| Q5 | 东芝 4 类功率 | 输入 1550W、输出 1000W、烧烤 1500W、蒸汽 1600W |
| Q6 | 方太图片状态 | 来源图集明确暂无图片；不记为 OCR 失败，不扩大到所有来源 |
| Q7 | 松下菜单数差异 | HTML 58 与 OCR 46 并列引用；保留差异和当前复核状态 |
| Q8 | 东芝 OCR 功率 | 列出原 OCR 标签/数字，由参数页支持对应关系，准确说明逐项复核状态 |

复核分为答案、引用定位、工具轨迹、文件完整性四项。消费者只能读独立目录中的文字；外部搜索、图片工具、目录外事实或金标不能成为通过依据。

## 消费运行条件

- 复用仓库已锁定的官方 Codex CLI 0.147.0；使用当前配置模型 gpt-5.6-sol，两组均 low 推理。
- 每题使用新的临时消费目录和 ephemeral 上下文；不恢复历史会话。官方 CLI 使用现有 ChatGPT 登录，原始认证材料未复制到实验目录。
- 命令以 read-only 运行，关闭搜索、图片工具、插件、hooks、记忆、多 Agent；独立目录不加载仓库 AGENTS。实际工具轨迹仍逐项核对，不能只凭提示词认定隔离成功。
- 每个问题两组各运行一次、交替先后顺序。单题 120 秒，执行错误不重试，连续两次错误停止；累计输入 800,000 或输出 32,000 token 后停止发起新题。
- JSONL 保存命令、模型回答与官方 usage；输入计数包含多次工具往返的重复上下文，并单独记录 cached_input_tokens。费用不能直接用文件大小或总输入乘单一单价推算。

## 本轮实测结果

6 个 HTML 问题两组共 12 次运行全部完成，答案与引用均 6/6 通过；工具轨迹只有当前消费目录的文字读取，12 次消费前后文件哈希一致。Q7/Q8 尚未运行。文字消费可依据固定转写检查读取与引用；人工对照原图用于识别准确率和拟采用内容的核验，两类结论分别记录。当前工作进入加工规范评审，无需负责人先确认这些数字才能推进。

| 指标 | 原始文字 | Skill 加工包 |
| --- | --- | --- |
| 通过的 HTML 问题 | 6/6 | 6/6 |
| 输入 token | 457,082 | 283,691 |
| 其中缓存输入 | 290,816 | 149,248 |
| 非缓存输入 | 166,266 | 134,443 |
| 输出 token | 5,130 | 3,394 |
| 总耗时 | 322.04 秒 | 314.38 秒 |
| 文件读取命令 | 20 次 | 15 次 |

本轮六题合计的加工包输入 token 少 37.9%，非缓存输入少 19.1%，耗时相近；对照同时改变内容筛选、组织和导航说明，不能单独归因为 Skill 格式。Q1 跨型号查询的加工组输入较高（56,482 对 52,523）：消费者按型号加载整份材料，附带读取 OCR 与血缘。本次证明固定字段查询可用，并观察到组织收益；尚未证明各种查询都省 token，也未验证批量加工、其他格式、Windows/Linux 或其他 Agent 宿主。

合计 12 次消费输入 740,773 token（其中缓存 440,064）、输出 8,524 token、约 10 分 36 秒。此处是完整 A/B 试验开销；本地文字组装本身没有生成式模型费用。未把 token 换算成金额，现有 ChatGPT 登录的计费/额度口径另计。

ZIP 包包含 6 个文件，压缩后 14,614 bytes，压缩完整性检查通过。review.html 已在 Codex 内置浏览器实际打开，展示两组统计、逐题回答、包内资料及两处待人工确认的 OCR 原图。原图只用于负责人复核，不在 Skill 消费目录内。

具体回答、时间、usage、输入指纹和判定保存在本机 evaluation/；grading.json 的判定由本轮助手逐项对照冻结答案和实际读取轨迹得出，不声称人工确认了全部 OCR。小样单次结果不具备统计显著性。

## 复跑入口

先准备固定 input-manifest.json、ocr-review.json 和既有 OCR 结果，金标放在 evaluation/questions-gold.json、回答结构放在 evaluation/answer.schema.json。消费目录由脚本生成，不包含金标。

```sh
node scripts/knowledge-pack-sample.mjs --root data/knowledge-pack-ocr-20260903/sample-pack
node scripts/knowledge-pack-eval.mjs --root data/knowledge-pack-ocr-20260903/sample-pack
node scripts/knowledge-pack-report.mjs --root data/knowledge-pack-ocr-20260903/sample-pack
```

消费脚本拒绝覆盖已有题目运行目录。再次实验须使用新的结果目录并重新核对预算，保持已有证据可回查。
