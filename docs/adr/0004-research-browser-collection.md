# 教育研究平台页面使用成熟反检测浏览器采集

用户明确决定京东不走开放 API 或商务合作路线，首轮以科普教育研究为目的采集京东官方自营和经核实官方旗舰店的公开商品资料；淘宝登记为京东闭环后的下一平台来源。工程不得自研反检测、指纹或浏览器基础设施，优先使用 Apache-2.0 的 Patchright，并复用现有 Crawlee 队列、持久 Profile、状态分类和不可变证据保存。

## 边界

- 只采已确认范围内的公开商品资料，不采普通第三方商家、订单、购物车、账户资料或与商品知识无关的用户数据。
- 账号登录和验证码由用户在本地专用 Profile 完成；不读取密码，不自动解验证码，不切换账号规避限制。
- 并发固定为 1，默认不重试；风险页、登录页和空骨架必须被明确分类，不能伪装为成功。
- Cookie、认证 Header 和 Profile 不进入日志、Git、Codex 输入或知识包。登录态原始快照属于本地受限资料；按 ADR-0005 只有白名单可加工资料投影能进入知识加工。
- Patchright 不能直接写入生产依赖。阶段 1A 先以隔离 POC 验证至少一个正常 SKU、一个异常状态、内容完整性和中断恢复，再决定 Provider 组合方式。
- 页面适配只实现来源特有的薄配置和提取规则；队列、浏览器控制、滚动、指纹和证据存储继续复用成熟开源组件。

## 已验证事实

同一台本机 Chrome 的本地空白页对照中，原版 Playwright 报告 `navigator.webdriver=true`，Patchright 报告 `false`。同一京东登录 Profile 下，S01 由原版 Playwright 进入风险响应页，改用 Patchright 后返回真实商品页、HTTP 200 且型号存在；Crawlee＋Patchright 已保存 HTML、纯文本、截图、脱敏资源路径和 SHA-256。一次过早快照只保存骨架屏并被纠正为必须等待目标内容；未登录的新 Profile 当前进入正常登录页，而不是商品成功。隔离 Crawlee 3.18.1 还通过了公开样本中断恢复：首轮只完成 1 条，重启后只补齐剩余 2 条并正常退出。
