# 知识产线工序与验收规范

日期：2026-09-04。状态：阶段 2 正式实现基准。阶段顺序见 [ROADMAP.md](ROADMAP.md)，当前证据见 [PROGRESS.md](PROGRESS.md)，技术依据见 [RESEARCH.md](RESEARCH.md) R-014～R-019，成品格式决定见 [ADR-002](../adr/002-agent-skill-package.md)，审核分流决定见 [ADR-003](../adr/003-knowledge-review-routing.md)。

## 简单说明

知识产线把一次或多次完整采集批次生产成可安装的 Agent Skill：

1. **选料**确定采用哪个抓取任务的哪些完整批次。一个批次代表一次可追踪的采集结果，例如本周的 v1 和下周的 v2；用户不逐个勾选网页或图片。
2. **加工**把批次里的全部已准入原件固定下来，按来源结构提取字段和正文，检查图片，记录缓存、耗时与逐件失败，并找出需要自动判断或人工取舍的问题。
3. **审核**把机器不能可靠完成的事情分流：加工失败和空内容交回加工；内容归属、OCR 和图片由系统整批判断并自动入包或隔离；只有同一字段的来源冲突交给人作整组取舍。正常结构化内容直接通过。
4. **版本与发布**把当前可用内容冻结成标准 Skill ZIP，校验目录、脚本、数据、来源、图片和哈希。发布后该版本不再变化，后续批次形成新版本。

最终得到一个以 `SKILL.md` 为入口、带查询脚本、结构化数据、来源谱系和合格图片的版本化 ZIP。本项目负责生产与导出；具体 Agent 宿主安装、启用和版本切换在后续跨工程完成。

## 页面信息与设计用意

| 页面 | 必须展示 | 设计用意 | 不在主界面展开 |
| --- | --- | --- | --- |
| 选料 | 抓取任务、其历次批次、采集时间、记录/附件数、来源完成度、批次状态、当前选择统计和保存动作 | 用批次建立可重复生产边界；用户能比较 v1/v2 并明确本次输入 | 单条网页、图片、型号搜索和产物说明；它们不影响本页的批次决定 |
| 加工 | 当前批次的四段进度、原件数、缓存复用、自动通过数、待审核问题数、失败原件、历史运行 | 回答“整批是否处理完、哪里出错、成本怎样”；正常结果只显示汇总 | 每条正常资源卡片；只有失败项需要用户动作 |
| 审核 | 人工问题数、自动处理状态、加工异常、已处理结果；人工问题展示整组来源证据和一个决定动作 | 人只处理来源冲突等必须由负责人取舍的问题；OCR 与图片展示整组结果统计，不提供逐行勾选或手工修图工具 | 已自动通过的正常字段、逐行 OCR 候选、图片处理参数、批次说明和重复的工序解释 |
| 版本与发布 | 建包门、隔离数量、版本列表、变更摘要、固定高度的包内文件预览、大小、SHA-256、发布确认和 ZIP 下载 | 比较并冻结一份可验证成品；在文本、JSON 和图片间切换时保持视图稳定 | 宿主安装教程、Agent 会话逻辑和其他页面的工序说明 |

页面中的每个操作都对应一个明确结果：选择批次改变输入修订；开始加工创建一次冻结运行，并在提取完成后自动排队内容与图片判断；人工审核只改变冲突内容的处置修订；生成版本冻结当前入包结果；发布确认该 ZIP 可导出。查看、筛选和预览不改变领域状态。

## 输入边界

- Source Dataset 是原件事实源；Knowledge Processing 只保存 `{taskId, batchId}` 和运行时冻结的原件引用，不覆盖 Snapshot 或 Asset。
- 同一知识包一次选择只包含同一 Capture Task 下的不重复批次，最多 20 个批次；单次运行最多 20,000 份已准入原件。
- 批次是否可用以该批次每个计划来源的**最新 Source Run** 为准：来源齐全且全部完成时才能保存选料和开始加工。恢复或重试产生的旧 Run 继续留作审计，但不重复进入本次输入。
- 批次中的 accessible、accepted、有完整 lineage、公开安全 URL、受支持格式且大小在 1 byte～20 MiB 的原件进入加工；其他原件逐项记为排除，不要求用户手工挑选。
- 运行创建时冻结原件引用、SHA-256、配置和工具版本。批次后续变化形成新的运行，不改写旧运行。

## 加工工序

| 工序 | 自动处理 | 输出与合格条件 |
| --- | --- | --- |
| 固定原件 | 展开所选批次的最新完成来源，验证归属、bytes、SHA-256 和读取边界 | 冻结输入列表与输入哈希；重复内容保留全部来源关系 |
| 提取与整理 | 已验证来源 HTML 由对应 adapter 保留原字段、原值与定位；图片进入检查/OCR/副本分支；其他格式按已通过调研门的组件处理 | 每份原件有完成、失败或排除结果；数值、单位、否定、条件和来源不被补猜 |
| 批量判断 | 检查空内容、非结构化归属、OCR 文字、图片质量/水印和已知字段冲突；内容与图片问题按有界分组进入自动阶段 | 正常结构直接通过；高置信且有原件证据的内容采用，其余隔离；图片生成副本后由视觉模型对照原图验收；冲突生成整组人工问题 |
| 计算准入 | 合并规则、当前代次的自动结果与绑定内容哈希的人工决定，传播同一事实组及其附件依赖 | `accepted`、`quarantined`、`excluded`、`openIssues` 和建包缺口由服务端统一投影 |

每份原件的 120 秒预算独立计算；单份超时只结束该原件。相同原件哈希、工具版本与配置命中 `cacache`。停止、继续和失败均写入同一持久运行，避免用“新一轮加工”掩盖未完成工作。只有批次或加工规则发生变化时才创建新的运行。

## 审核问题

审核回答的是“问题应由加工、AI 还是人处理，以及什么证据足以形成最终决定”。当前分流如下：

| 问题 | 首要处理者 | 操作与入包结果 |
| --- | --- | --- |
| 空内容/加工失败 | 加工系统 | 回到失败原件继续加工；当前没有候选进入包 |
| 内容归属 | 自动判断 | 高置信且与当前知识范围、来源定位一致的片段进入准入，其余片段自动隔离 |
| OCR 文字 | 自动判断 | 整图读取原图、识别文字、置信度和坐标；只采用内容准确且属于当前对象的候选，水印、装饰文字、残缺文字和低置信候选自动隔离 |
| 图片处理 | 自动处理 | 清晰无水印图片生成标准 PNG；可安全定位的水印按 OCR 四边形生成遮罩并修补；遮罩过大、边界不安全或处理失败时整图隔离 |
| 图片副本质量 | 自动判断 | 视觉模型对照原图与处理副本；内容完整、无修补痕迹且无水印残留才入包，否则自动隔离 |
| 来源冲突 | 人工整组审核 | 对照各来源与适用条件保留一个成立值或全部排除；这是会改变成品事实且无法仅靠置信度决定的负责人取舍 |
| 历史图片副本 | 只读保留 | 旧运行的副本和决定继续可审计；新运行统一走自动处理与自动视觉验收 |

自动判断在加工完成后排队，按最多 32 个问题、16 份原件分组执行并累计写入同一记录，避免数千张图片形成一个无界请求。外部结构化输出中的 `null` 只在协议入口归一化；覆盖、候选范围、图片动作或遮罩坐标不合格时按同一错误最多完整纠正一次。只有高置信采用结果进入确定性准入，其他结果保持隔离。记录同时绑定加工代次、审核修订和问题指纹，任一变化都会使旧结果失效。人工冲突决定必须记录理由并绑定候选内容哈希。若运行未完成或没有任何可用内容，建包门关闭。

## 标准 Skill 产物

新版本 ZIP 只有一个顶层目录，目录名与 `SKILL.md` 的 `name` 相同：

```text
<skill-name>/
├── SKILL.md
├── scripts/
│   ├── query.mjs
│   └── validate.mjs
├── assets/
│   ├── data/
│   │   ├── catalog.json
│   │   └── provenance.json
│   └── images/
│       └── <approved-image>.png
└── references/
    ├── catalog.md
    └── source-boundaries.md
```

- `SKILL.md` 只放触发描述、适用边界和读取步骤，详细内容按需从其他目录读取。
- `catalog.json` 是按对象组织的结构化知识；每条事实保留原标签、原值、定位和 `sourceIds`。
- `provenance.json` 保存源 URL、Snapshot/Asset 标识、哈希、捕获时间和批次引用。
- `query.mjs` 提供本地确定性查询，不要求联网或额外依赖；Perfume 类枚举/筛选知识可在宿主侧映射为 search/list/summarize 工具，Tutor 类关系知识可映射为聚合候选查询。
- `validate.mjs` 检查入口、数据结构、来源引用和图片引用；服务端同时校验 ZIP 路径白名单、CRC、bytes 和 SHA-256。
- `assets/images/` 只包含通过自动处理安全门的副本或历史已验收副本。原图、遮罩、隔离 OCR、审核记录和加工缓存保存在内部产线区。

候选版本的输入摘要绑定原料、当前自动建议、人工决定和图片副本哈希；任一内容变化后必须生成新版本。发布读取已冻结 ZIP，不在下载时重新生成。历史版本继续按其原始格式与哈希下载；新建版本统一使用 `agent-skill` 格式。

## 复用与产品代码边界

- 成熟组件：Agent Skills 目录规范、Graphile Worker、Drizzle/PostgreSQL、cacache/canonicalize、Cheerio、fflate、React/Radix/TanStack Query、既有 Codex App Server，以及已验证的 RapidOCR/OpenCV 本地环境。
- 项目资产：Source Dataset 的不可变 Snapshot/Asset、来源身份、血缘、历史样包与图片证据。
- 产品代码：批次选择规则、输入冻结、来源 adapter 输出、问题分类与准入传播、Skill 内容组织、版本冻结及界面流程。这些职责直接表达本产品的事实与工序。
